**Description**:

Migrate the three remaining manual providers in `lib/features/settings/presentation/providers/settings_provider.dart` to `@riverpod` codegen, then rename every consumer of the old `settingsProvider` symbol to `settingsNotifierProvider` (the codegen-emitted name for the class-form notifier). This is the integration-gate task — by the end of this task, the codebase has zero manual `Provider<>` / `NotifierProvider<>` / `StreamProvider<>` declarations and every `settingsProvider` reference is renamed.

The three migrations:

1. **`settingsRepositoryProvider`** (function form, default `autoDispose`):
   ```dart
   @riverpod
   SettingsRepository settingsRepository(Ref ref) {
     final prefs = ref.watch(sharedPreferencesProvider);
     final dataSource = SettingsLocalDataSource(prefs);
     return SettingsRepositoryImpl(dataSource);
   }
   ```
   The codegen-emitted symbol is `settingsRepositoryProvider` — same name. No consumer rename needed for this one.

2. **`SettingsNotifier`** (class form):
   ```dart
   @riverpod
   class SettingsNotifier extends _$SettingsNotifier {
     // existing class body — build, _errors, errors getter, four setX methods —
     // copied verbatim. Only the `extends Notifier<AppSettings>` declaration changes
     // to `extends _$SettingsNotifier`.
   }
   ```
   The codegen-emitted symbol is `settingsNotifierProvider` — **renamed** from the old `settingsProvider`.

3. **`settingsErrorsProvider`** (function form, default `autoDispose`):
   ```dart
   @riverpod
   Stream<Failure> settingsErrors(Ref ref) {
     return ref.watch(settingsNotifierProvider.notifier).errors;
   }
   ```
   The codegen-emitted symbol is `settingsErrorsProvider` — same name. Note the inner reference to `settingsNotifierProvider.notifier` (renamed from `settingsProvider.notifier`).

Default `@riverpod` (autoDispose) is correct for `settingsErrorsProvider` because:
- The only listener is `SettingsScreen` via `ref.listen` while mounted.
- The provider exposes a broadcast stream of one-shot events (failures), not state to retain across screen unmounts.
- The underlying `StreamController` lives on `SettingsNotifier`, which is kept alive by `app.dart` watchers — so re-subscribing on screen remount works correctly.

Default `@riverpod` (autoDispose) is correct for `settingsRepositoryProvider` because the notifier holds a `ref.watch(settingsRepositoryProvider)` that keeps it alive transitively for the lifetime of `SettingsNotifier` — and `keepAlive: true` would be over-specifying intent.

**Notes**:
- **Deviation from plan — `SettingsNotifier` lifetime**: Plan said "default `@riverpod` (autoDispose)" for `SettingsNotifier`. Actual implementation uses `@Riverpod(keepAlive: true, name: 'settingsNotifierProvider')` for two correctness reasons confirmed by code review:
  1. The original `NotifierProvider<SettingsNotifier, AppSettings>` was non-autoDispose by default. Default `@riverpod` (autoDispose) would close and re-create the `_errors` `StreamController` between sequential `container.read()` calls in unit tests, breaking "multiple sequential emissions" assertions. `keepAlive: true` preserves the original semantic.
  2. **Codegen behavior surprise**: Riverpod 4.x codegen strips the `Notifier` suffix from class names before appending `Provider`. So `class SettingsNotifier` would emit `settingsProvider` (NOT `settingsNotifierProvider`) without an explicit `name:` parameter. The `name: 'settingsNotifierProvider'` parameter is REQUIRED to get the canonical Riverpod 3.x class-form symbol name. The code reviewer initially flagged the parameter as redundant; repair agent verified it is required (removing it produces 18+ `undefined_identifier` errors).
- **Code review verdict**: REQUEST CHANGES → APPROVE after repair. Fixed: 1 Critical (dartdoc lie at line 127 claimed "Non-`autoDispose`" while annotation was `@riverpod`/autoDispose — corrected to accurately describe autoDispose semantics) + 1 Warning (stale `[NotifierProvider]` type ref at line 4 replaced with behavior description).
