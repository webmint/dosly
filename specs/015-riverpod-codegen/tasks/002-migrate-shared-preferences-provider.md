**Description**:

Convert the manual override-only provider in `lib/core/providers/shared_preferences_provider.dart` to the codegen form. The throwing-placeholder pattern survives unchanged — only the declaration syntax changes from a top-level `final` `Provider<>` factory to a `@Riverpod(keepAlive: true)`-annotated function. Run `build_runner` to emit the `.g.dart` file and verify `lib/main.dart`'s `sharedPreferencesProvider.overrideWithValue(prefs)` continues to compile and behave identically.

`keepAlive: true` is the explicit codegen option (not the default `autoDispose`) because:
1. The provider is overridden in the root `ProviderScope` at startup with a real `SharedPreferencesWithCache` instance — there is exactly one instance for the lifetime of the app.
2. Auto-disposing it would never fire in practice (the override holds it alive), but `keepAlive: true` makes the contract explicit and documents intent.
3. The codegen-emitted symbol `sharedPreferencesProvider` is structurally compatible with `.overrideWithValue(...)` — `main.dart` needs no edit.

This is the **first `@riverpod`-annotated provider in the codebase**. Get the pattern right here so Task 003 (the class-form migration) can copy it cleanly.
