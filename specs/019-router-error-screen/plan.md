# Plan: Router Error Screen for Unmatched Routes

**Date**: 2026-05-18
**Spec**: [spec.md](spec.md)
**Status**: Approved

## Summary

Add an `errorBuilder:` parameter to the `GoRouter(...)` constructor inside the existing `appRouter` provider at `lib/core/routing/app_router.dart:36`, pointing to a private `_RouterErrorScreen` widget declared in the same library. The widget renders a localized `Scaffold(AppBar, body)` with a `FilledButton` whose `onPressed` calls `context.go('/')`. Three new ARB keys are added across all three locales and `flutter gen-l10n` regenerates the `lib/l10n/app_localizations*.dart` family. One new `testWidgets` in `test/core/routing/app_router_test.dart` exercises an unmatched path and verifies recovery.

## Technical Context

**Architecture**: `lib/core/routing/` — the routing composition root (the documented exception to the "feature A never imports feature B" rule per `docs/architecture.md` line 247). Single layer; no `domain/` / `data/` / `presentation/` split needed because the error screen has no business logic, no state, and no data flow.

**Error Handling**: N/A at the value level — the error screen is the *fallback UI* for an upstream framework error (no `GoRoute` matched). There are no fallible operations inside the screen itself. The `context.go('/')` call is a synchronous router state change with no failure mode.

**State Management**: None. `_RouterErrorScreen` is a `const`-constructible `StatelessWidget` that reads `context.l10n` (an InheritedWidget lookup) and nothing else. No Riverpod consumer, no `ref.watch`, no listenable subscription.

### Key Design Decisions

| Decision | Chosen Approach | Why | Alternatives Rejected |
|---|---|---|---|
| Where the error widget lives | Private `class _RouterErrorScreen extends StatelessWidget` in `lib/core/routing/app_router.dart` | Co-located with sole consumer; `const`-constructible so the `errorBuilder` closure becomes `(context, state) => const _RouterErrorScreen()`; shows up in the Flutter Inspector under its own name (a closure-only form would not); KISS — one file. | (A) `lib/core/widgets/app_error_screen.dart` — speculative reuse for a 15-line widget. (B) Inline closure returning a `Scaffold` directly — no `const`; harder to set a breakpoint; doesn't appear named in the inspector. |
| `errorBuilder` style | `errorBuilder: (context, state) => const _RouterErrorScreen()` | Single-expression body; no use of `state` — we deliberately do NOT display the attempted path (spec §6 out-of-scope item). | `errorBuilder: (context, state) { return _RouterErrorScreen(uri: state.uri); }` — would leak unverified user input to the UI and require an extra ARB string for "We couldn't find {path}". |
| `AppBar.automaticallyImplyLeading` | `false` | Recovery should be deterministic via the explicit `FilledButton`. The error path has no guaranteed previous frame to pop to (an inbound deep link is the canonical case), and a back arrow that pops to nothing is worse UX than no back arrow at all. | `automaticallyImplyLeading: true` (default) — unpredictable behavior depending on how the user reached the error screen. |
| Recovery navigation method | `context.go('/')` | Replaces the current location with `/`; `StatefulShellRoute.indexedStack` re-mounts at the Today branch root; route history is cleared. Matches `docs/architecture.md` §"Conventions". | `Navigator.of(context).pushReplacement(...)` — bans by `docs/architecture.md` §"Conventions" line 249, leaves the bad URL in router state. `context.pop()` — pops to the previous router stack entry which may not exist or may be another error. |
| Button widget type | `FilledButton` | Already standard for primary actions in dosly screens (e.g., settings, theme preview). Material 3 emphasis hierarchy treats `FilledButton` as the page's primary action. | `ElevatedButton` (legacy M2), `TextButton` (too low-emphasis for a recovery action), custom button (banned by KISS). |
| Body layout | `Padding(EdgeInsets.all(24)) → Column(mainAxisAlignment: MainAxisAlignment.center, mainAxisSize: MainAxisSize.min, crossAxisAlignment: CrossAxisAlignment.stretch)` wrapping a `Text` and `FilledButton` with a `SizedBox(height: 16)` between | Mirrors `lib/features/meds/.../meds_screen.dart` and `lib/features/settings/.../settings_screen.dart` body layouts; `crossAxisAlignment: stretch` makes the `FilledButton` span the available width per Material 3 guidance for full-bleed primary actions on error/empty states. | A `Center(child: Column(...))` — leaves the button narrow and floating, doesn't match dosly's existing empty-state patterns. Wrapping in `SafeArea` — `Scaffold` already does this for `body:`. |
| Theming | Inherit from `Theme.of(context)` only — no color/text-style literals | Constitution §1 implies Material 3 stack throughout; CLAUDE.md "Always #11" + Lessons in `MEMORY.md` reject color literals. | Setting `backgroundColor: Theme.of(context).colorScheme.errorContainer` to visually emphasize the error — adds a hardcoded semantic decision the spec doesn't ask for; "page not found" is closer to an empty state than to a destructive error. Default surface is correct. |
| ARB key naming | `errorScreenTitle`, `errorScreenBody`, `errorScreenGoHome` | Matches bug 008's Fix Notes verbatim; follows the project's `xxxYyyZzz` camelCase convention (compare `settingsAppearanceHeader`, `medsAddTitle`); `errorScreen` prefix groups all keys for this screen so future "open settings" / "report problem" additions slot in adjacent if ever needed. | `routerErrorTitle` — emphasizes the cause (router) over the user-facing surface (a screen). `notFoundTitle` — more specific to one error mode; we may want to reuse the screen for other route-evaluation errors later if `onException:` ever lands. |
| `@key.description` metadata | English ARB only; describes both audience (translators) AND code consumers (because `flutter gen-l10n` mirrors descriptions into the abstract getter's dartdoc — MEMORY L203) | Single source of truth; matches every other ARB key in `app_en.arb`. | Skipping descriptions — translators lose context; IDE-hover dartdoc on `AppLocalizations.errorScreenTitle` becomes empty. |
| Test file location | Append Test 7 to existing `test/core/routing/app_router_test.dart` `group('appRouter', ...)` | Reuses `_pumpRouter`; keeps all router behavior tests in one file; mirrors existing Test-numbering convention. | A new `app_router_error_test.dart` file — splits closely-related tests, duplicates the `_FakeSettingsRepository` and `_pumpRouter` setup. |
| Test target path | `/nonexistent` | Short, unambiguous, no risk of accidental match against a future route (no route will ever be named `nonexistent`). | `/foo/bar/baz` — slightly more "deep-link-shaped" but no test value; `/settings/nonexistent` — could match if `/settings` later gains children. |
| Doc update style | One additive sentence as a new bullet under §"Routing" → "Conventions" | `docs/architecture.md` already has 5 bullets in that subsection; adding a 6th is the lowest-drift edit. MEMORY L192 / bug 012 warn against rationale-paragraph rewrites. | Adding a full subsection "§ Error handling" — over-architects for a 1-builder fix and creates a doc surface that wants more content than the fix actually provides. |

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `errorBuilder` actually renders *inside* the `StatefulShellRoute` in go_router 17.2 (would surface `AppBottomNav` underneath) | Low | Med | Test 7's `find.byType(AppBottomNav) findsNothing` assertion (AC-8) catches this directly. If it fails, fall back to wrapping the screen in an explicit `Scaffold(body: ...)` — already done — or use `parentNavigatorKey` on the registered shell to ensure the error screen escapes the shell. |
| `flutter gen-l10n` fails because one locale ARB is missing a key | Med | Low | Atomic edit: all three ARB files updated in the same task (`/breakdown` will keep them in one task per spec §4 Affected Areas). `dart analyze` post-gen surfaces any missing-getter error immediately. |
| `find.text('Page not found')` matches the home-screen "Theme preview" demo text or another fixture | Low | Low | Verified by grep — the string is unique to the new key. Test pins `locale: const Locale('en')`. |
| The `Padding(EdgeInsets.all(24)) + Column + stretch` body layout breaks layout assertions on narrow devices (e.g., golden-test breakage) | Low | Low | No existing golden tests on `app_router.dart`. New test only asserts widget *presence*, not pixel layout. |
| `_pumpRouter` doesn't fully bootstrap the AppLocalizations delegate before the first `pumpAndSettle`, causing `context.l10n` to crash | Low | High | The 6 existing tests already use `context.l10n` paths (e.g., bottom nav `Today`/`Meds`/`History` labels) and pass. `_pumpRouter` wires `AppLocalizations.localizationsDelegates` and pins `locale: 'en'` — proven correct. |
| Test 7's `context.go('/nonexistent')` fails to trigger `errorBuilder` because go_router 17.2 silently coerces unknown paths to `/` instead | Very Low | High | Verified against context7 docs: `errorBuilder` is a documented top-level GoRouter parameter for exactly this case (since go_router 0.4.0 and stable through 17.x). If it doesn't fire, the test fails fast on the title assertion. |
| `_RouterErrorScreen` private class triggers an unused-element lint on the library | Very Low | Low | The class is referenced exactly once from the `errorBuilder` closure. `dart analyze` does not flag a referenced private class. |
| Bumping `docs/architecture.md` causes merge conflict with concurrent doc work | Very Low | Low | Spec 019 is the only spec in flight; main is clean per `git status`. |
| AC-15 doc bullet drifts away from the actual `_RouterErrorScreen` body over time | Low | Low | Bullet names *behavior* ("renders outside the StatefulShellRoute", "Go to home FilledButton") not internal implementation details. Stable for the lifetime of the widget. |
