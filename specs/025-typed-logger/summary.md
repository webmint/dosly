## Feature Summary: 025 — Typed Logger with PHI Sanitize Layer

### What was built
A typed logging pipeline for dosly that is safe for sensitive health data. Every log record flows through a single, unbypassable sanitization choke point that strips PHI (medication names, dosages) and platform internals (filesystem paths, raw exception strings) before anything is written — satisfying the constitution's long-deferred §7.1/§4.2.1 requirement (Bug 017). The logger is a no-op in release builds (dosly has no telemetry), and the app's router error path is wired up as the first real consumer.

### Changes
- Task 1: Add `logging` dependency — added the official Dart-team `package:logging` (`^1.3.0`).
- Task 2: Implement the sanitizer — pure `sanitizeRecord(LogRecord, {includeErrorDetail})` → `SanitizedLog`, with an exhaustive, redact-by-default `Failure`-aware redactor (CWE-209/532 mitigation).
- Task 3: Sanitizer test suite — 18 tests including the 3 mandatory PHI leak tests and one per `Failure` variant.
- Task 4: Logger provider — keep-alive `loggerProvider` configures `Logger.root` with one sanitizing listener; release no-op via `Level.OFF`; idempotent registration.
- Task 5: Logger pipeline tests — 6 tests covering level selection, release suppression, idempotent single-emit, and provider wiring.
- Task 6: Router pilot + startup registration — `errorBuilder` logs routing failures (sanitized, once per error) while keeping the error screen unchanged; `AppBootstrap` registers the pipeline at startup.
- Task 7: Architecture docs — removed the stale "deferred to Bug 017" note and documented the logging pipeline.

### Key decisions
- **Backend = `package:logging`**: its single `Logger.root.onRecord` listener is a *structural* sanitize choke point — bypass is impossible by construction (a bare `dart:developer` wrapper would rely on a lint instead).
- **Sanitizer is a pure function in its own file**: testable in isolation; exhaustive sealed `switch` over `Failure` with no `default:` so a future variant breaks compilation and forces a redaction decision.
- **Release no-op via `Level.OFF`**: `levelFor(isRelease: kReleaseMode)` filters every record at the root before any allocation — zero cost, honoring the no-telemetry privacy posture.
- **Three testability seams** (pure `levelFor`, injectable `LogSink`, explicit-param `configureLogging`): every AC verifiable without toggling compile-time consts or intercepting `dart:developer`.

### Deviations from plan
- Task 6: Plan specified `GoRouter.onException` for router-error logging. go_router 17.2.0 **asserts** that `onException`, `errorPageBuilder`, and `errorBuilder` are mutually exclusive, so using `onException` would have removed the existing `_RouterErrorScreen`. Used the plan's documented fallback instead — log inside `errorBuilder` with an `identical()` once-per-error guard, keeping the error screen byte-identical.
- Task 4 (post-review): `configureLogging` was made idempotent (cancel-before-register via a module-level subscription) to robustly satisfy AC-3 independent of caller disposal — caught in code review.
