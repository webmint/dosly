- **lib/features/settings/data/datasources/settings_local_data_source.dart:80** — Asymmetric legacy-type resilience; sibling getters encode the same rule with different robustness, and the dartdoc lies by omission about a failure mode the sibling treats as real. *(architect)*

  ```

### Security Regressions

- **android/app/build.gradle.kts:37** — Release artifact signed with the debug keystore (CWE-321: use of well-known cryptographic key). *(security-reviewer)*
  Evidence:
  ```
      buildTypes {
          release {
              // TODO: Add your own signing config for the release build.
              // Signing with the debug keys for now, so `flutter run --release` works.
              signingConfig = signingConfigs.getByName("debug")

  Why it's wrong: The `release` build type is signed with the Android debug keystore — a universally-known key (`~/.android/debug.keystore`, password `android`). The in-file TODO confirms this is an unfinished scaffold placeholder. **Context that lowers practical impact:** constitution §1 states "Distribution: Personal use (no app store distribution required)," so there is no store-update forgery vector today — but this must be fixed before any genuine release build leaves the developer's machine.
  Remediation: Generate a dedicated release keystore (`keytool -genkey -v -keystore dosly-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias dosly`), store credentials outside VCS (git-ignored `key.properties` or CI env), and wire a real `signingConfigs.create("release") { ... }`. Remove the debug fallback before `flutter build appbundle/apk --release`.
  Confidence: Certain
  Tags: (none)
